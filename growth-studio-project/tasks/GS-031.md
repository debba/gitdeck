- Add public store reads for one plan and repository-filtered plans. The structured answer is keyed by stable slot key and supplies a confirmed pillar, one-line angle, HTTP or HTTPS source URLs, and CTA. Normalize it against the requested slots and profile; persist the CTA in `GrowthContentItem.summary` because there is no separate CTA column.
- Persist one active `content_plans` snapshot and its `content_items` atomically. Items use the assigned channel, format, pillar, angle, sources, CTA summary, `status='idea'`, slot `scheduledFor`, empty draft/media fields, and a planner generation version. Do not write partial plans.
- When AI is not configured, or returns no usable assignments, use a deterministic evidence-grounded assignment for every slot and set `usedFallback: true`; `aiEnabled` continues to report configuration state. Configured-provider request failures return the existing typed AI error response without persisting a plan. Tests cover one-call generation, normalization, fallback, atomicity, account scope, overlap validation, and list ordering.

Acceptance:

- A valid request creates exactly one active plan and one idea per deterministic slot; no-AI generation is deterministic; malformed, overlapping, cross-account, and partial generations cannot create rows.
