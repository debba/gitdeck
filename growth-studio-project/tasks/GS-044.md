# GS-044 — Browser image rasterization

**Phase:** Phase 4 — Media

- Create `src/utils/growth/rasterize.ts` and `tests/utils/growth/rasterize.test.ts`. Do not add a server module, route, native dependency, committed binary fixture, or test under `src`.
- Add pure helpers that parse trusted intrinsic SVG width/viewBox values, calculate bounded output dimensions, sanitize a PNG download filename, and choose the 2x raster size. Reject zero, non-finite, malformed, or over-limit dimensions deterministically and cover the helpers with mirrored unit tests.
- Add a browser-only `rasterizeGrowthImageToPng` operation that accepts an image `Blob`, decodes raster images or SVG through an object URL, draws onto a canvas at 2x while preserving aspect ratio, and resolves a `image/png` blob. Cap canvas dimensions and total pixels, use a white or transparent background as explicitly requested by the caller, and always revoke object URLs on success or failure.
- Keep DOM creation and `canvas.toBlob` at the side-effect boundary while the dimension and filename decisions remain pure. Return typed errors for decode, canvas, taint, unsupported type, and PNG encoding failures so later UI can offer a download fallback.
- Tests cover viewBox and explicit dimensions, 2x scaling, aspect ratio, dimension/pixel caps, filename normalization, unsupported input, mocked decode/canvas success, failed encoding, and object-URL cleanup.

Acceptance:

- Generated SVG and supported image blobs can become bounded 2x PNG blobs entirely in the browser, with deterministic pure sizing helpers and cleanup, while the server remains free of rasterization and native image packages.
