# GS-040 — Account-scoped asset persistence and serving

**Phase:** Phase 4 — Media

- Create `src/server/growth/assets.ts` and `tests/server/growthAssets.test.ts`. Extend `src/types/growth.ts`, `src/server/growth/store.ts`, `src/server/routes/growth.ts`, `src/api/growth.ts`, `tests/server/growthStore.test.ts`, and `tests/server/growthRoutes.test.ts` with account- and repository-scoped asset creation, lookup, listing, upload, and file reads over the existing `growth_assets` table; do not add a second asset table.
- Add `GET /api/growth/assets?repo=owner/name`, bounded raw-body `POST /api/growth/assets` with allowlisted `repo`, `filename`, `title`, `alt`, `width`, and `height` query metadata, and authenticated `GET /api/growth/assets/:id/file`. Add typed `fetchGrowthAssets`, `uploadGrowthAsset`, `fetchGrowthAssetFile`, and `buildGrowthAssetFileUrl` client helpers. Unknown or duplicate query fields, invalid dimensions, unsupported content types, malformed repositories, and cross-account IDs must fail without creating a row or file.
- Accept PNG, JPEG, WebP, GIF, MP4, and WebM uploads up to 25 MiB. Stream with an enforced byte limit, write through a temporary file, then atomically rename to a server-generated UUID filename below `DATA_DIR/growth-assets/`; persist only a normalized relative path. Clean up temporary or final files when validation or persistence fails.
- Resolve every served path against the asset root and reject traversal, missing files, URL-only assets, and generated assets not yet supported by this task. Return the allowlisted MIME type, exact length, `Cache-Control: private, no-store`, and `X-Content-Type-Options: nosniff`; never expose a filesystem path in an API response or through the existing public static-file handler.
- Keep `listGrowthAssets` compatible with `src/server/growth/drafter.ts`. Tests cover schema reuse, stable list ordering, account and repository scope, MIME and size bounds, atomic cleanup, path containment, authenticated reads, and binary round trips. Do not add a native dependency.

Acceptance:

- A supported upload creates one account-scoped `GrowthAsset` and can be read only through its authenticated asset ID; invalid, oversized, traversing, missing, and cross-account requests cannot leak bytes or leave orphaned files or rows.
