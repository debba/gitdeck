# GS-030 — Deterministic editorial plan slots

**Phase:** Phase 3 — Editorial plan

- Create `src/utils/growth/planSlots.ts` and `tests/utils/growth/planSlots.test.ts`. Add the shared `GrowthPlanSlot` and slot-builder input types to `src/types/growth.ts`; do not introduce server-only duplicates.
- Implement a pure `buildGrowthPlanSlots` function for an inclusive plan period made of one to four complete ISO weeks (Monday through Sunday). It must use the profile's enabled channels, per-channel weekly cadence, positive-weight pillars, posting windows and IANA timezone. Disabled channels and zero cadence produce no slots.
- Give every slot a stable key, channel, matching existing `GoalProposalFormat` (`x-thread`, `linkedin-post`, `mastodon-post`, `post`, `discussion`, or `doc`), pillar ID, and UTC `scheduledFor`. Sort output by time, channel, and stable key. Distribute each channel's weekly count deterministically across the available posting windows; when none are configured, use an evenly spread 10:00 local-time fallback. Repeated calls with identical inputs must be byte-for-byte stable.
- Keep timezone conversion and weighted pillar allocation in this pure utility. Cover DST boundaries, zero-weight pillars, cadence counts across multiple weeks, empty posting windows, format mapping, stable ordering, and invalid or non-week-aligned periods.

Acceptance:

- Slot counts equal each enabled channel's cadence multiplied by the number of complete weeks; timestamps are valid UTC ISO strings in the requested profile timezone; weighted pillar assignment is deterministic and never selects a zero-weight pillar.
